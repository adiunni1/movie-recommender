# Movie Recommender

A head-to-head experiment comparing three recommendation approaches on the
[MovieLens](https://grouplens.org/datasets/movielens/) dataset, built to test one
specific question:

> **Does adding behavioral signal and content features actually beat a plain
> star-rating model — or is that just something people say?**

Rather than building one recommender, this project trains three on the same
data and measures them against each other:

| Stage | Model | Trained on | Metric | Result |
|---|---|---|---|---|
| 1 | **SVD** (`scikit-surprise`) | Explicit star ratings | RMSE | 0.8895 |
| 2 | **ALS** (`implicit`) | Implicit confidence scores | Precision@10 | 0.71% |
| 3 | **LightFM** (hybrid) | Implicit signal + genre/year content | Precision@10 | 1.31% |

**Result: LightFM beats ALS by ~85% on Precision@10.** Adding content features
(genre, year) on top of behavioral signal meaningfully improves ranking
quality over behavioral signal alone — the hypothesis held.

A live Streamlit demo lets you search any movie and compare what each of the
three models recommends, side by side.

## Why this project

MovieLens only ships explicit 0.5–5.0 star ratings. Real production
recommenders (Spotify, Netflix) rarely have the luxury of explicit ratings —
they infer taste from *implicit* behavior: did you finish the episode, skip
the track, rewatch the movie. To make a fair comparison possible on a dataset
that only has stars, I simulated that implicit layer: each star rating is
mapped to an assumed completion rate (a 5-star rating implies the viewer
almost certainly watched the whole thing; a 1-star implies they probably
bailed early), then converted into a confidence score using the
[Hu, Koren & Volinsky (2008)](https://ieeexplore.ieee.org/document/4781121)
formulation that underlies ALS-based implicit recommenders in production:

```
confidence = 1 + 40 × completion_rate
```

That one assumption is what makes stages 2 and 3 possible at all, and it's
the most opinionated engineering decision in the project — everything
downstream depends on whether that mapping is a reasonable proxy for real
engagement data.

## Pipeline

```
data_pipeline.py   →  download MovieLens, build explicit + implicit datasets,
                       one-hot encode genres, normalize year
train_models.py    →  chronological train/test split, train & evaluate
                       SVD → ALS → LightFM, save all three models
app.py             →  Streamlit demo: item-embedding similarity search
                       across all three models for any seed movie
```

**Chronological split, not random.** Each user's ratings are sorted by
timestamp; the most recent ~20% are held out as test. A random shuffle split
lets the model implicitly "see the future" (data leakage) and inflates
reported accuracy — sorting by time is what makes the Precision@10 numbers
above trustworthy rather than optimistic.

**Item-embedding similarity, not popularity.** Every model (SVD, ALS,
LightFM) learns a latent vector per movie internally. The demo app pulls
those vectors directly and ranks by cosine similarity to the seed movie, so
recommendations genuinely change based on what you search for — an earlier
version of the demo fell back to popularity-based results when a lookup
missed, which silently made all three tabs look identical regardless of the
underlying model.

## What worked / what didn't

- **Worked:** the implicit-confidence hypothesis. LightFM's hybrid approach
  (behavior + genre/year content) outperformed both the explicit baseline and
  implicit-only ALS, which is the result the whole project was designed to
  test.
- **Didn't work out of the box:** `lightfm==1.17` (the last PyPI release)
  doesn't build on Python 3.12 — `setup.py` references `__builtins__.X`
  (broken under modern setuptools) and its shipped Cython `.c` files touch
  `PyLongObject.ob_digit`, which CPython 3.12 removed. Fixed by patching the
  source (`vendor/lightfm-1.17-patched/`) and vendoring a prebuilt wheel
  rather than depending on an abandoned PyPI release.
- **Worth noting honestly:** absolute Precision@10 values (0.71% / 1.31%) are
  low in absolute terms — expected on MovieLens-small, where ~9,700 movies and
  sparse per-user history make top-10 hits genuinely hard. The *relative*
  improvement between models is the meaningful signal here, not the absolute
  number.

## Running it

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install --no-build-isolation vendor/lightfm-1.17-cp312-cp312-macosx_11_0_arm64.whl

python data_pipeline.py   # downloads MovieLens, builds data/processed/
python train_models.py    # trains & evaluates all three models into models/
streamlit run app.py      # launches the comparison demo
```

`data/` and `models/` are gitignored — both are fully regenerated by the two
commands above.
